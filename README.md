# NexusOps

## 后端启动

安装 Docker Desktop 并启动 Docker 引擎，在项目根目录运行 `docker compose up --build`。启动后访问 http://localhost:8887/docs，健康检查为 `/health`。数据库迁移需手动执行；MySQL 数据保存在 Docker volume 中。Compose 中的密码仅供本地开发。

本地开发：进入 `backend`，复制 `env/.env.dev.example` 为 `env/.env.dev` 并填写配置，运行 `uv sync`，然后在 `backend` 目录使用 `uv run main.py --env=dev` 启动开发环境；生产环境填写 `env/.env.prod` 后使用 `uv run python -m app --env prod --host 0.0.0.0`。迁移使用 `NEXUSOPS_ENV` 选择环境（PowerShell 示例：`$env:NEXUSOPS_ENV="dev"; uv run alembic upgrade head`），执行前须确认目标数据库和迁移内容。进程环境变量优先于环境文件。运行测试：`uv run pytest`。

商户、商品提供创建、分页列表、详情、部分更新与删除。商户有商品时禁止删除。商户和商品写操作已接入认证和商户成员权限校验；尚未实现审计，仅用于本地开发，不能暴露到公网或用于真实数据。健康检查仅表示 API 进程存活，不检查依赖服务。

前端参考源码位于 `references/`，不属于项目应用代码。

## 环境与数据库

配置统一位于 `backend/env/`，`NEXUSOPS_ENV` 可取 `dev`、`test`、`prod`，进程环境变量优先。开发库为 `nexusops`，测试库为 `nexusops_test`；生产配置须在实际部署时填写。环境文件含凭据，不纳入版本控制。

现有 `uv run pytest` 使用独立的内存 SQLite，不会清空 MySQL。需要执行 MySQL 测试或迁移时，明确选择测试环境：PowerShell 中执行 `$env:NEXUSOPS_ENV="test"`；执行任何破坏性操作前检查连接目标。迁移前须确认数据库模型；不要把未确认的旧迁移应用到任何环境。

## 开发环境模拟登录

开发和测试环境可调用 `POST /api/v1/auth/codes`，传入手机号及 `register` 或 `login` 用途，在响应中获取模拟验证码；不会发送真实短信。验证码只保存在当前进程内，重启失效，不支持多进程共享，生产环境禁用模拟发送。随后可通过 `/api/v1/auth/register`、`/api/v1/auth/login` 或 `/api/v1/auth/login/sms` 完成注册和登录。`/docs` 提供交互式接口文档。

JWT_SECRET 必须使用足够长的随机值；开发及测试环境各自使用独立密钥。当前刷新令牌为无状态令牌，在有效期内不能主动撤销，正式部署前需实现令牌撤销和登录频率限制。商户和商品写操作要求商户管理员权限。

## 管理端前端

启动后端后，在 `frontend/apps/management-web` 运行 `npm install`，然后在 `frontend` 运行 `npm run dev`，浏览器打开 http://127.0.0.1:3001。开发服务器将 `/api` 请求代理到 `127.0.0.1:8887`。页面提供账号登录、模拟验证码登录和注册；当前登录成功页面仅用于联调，不代表已获得管理权限。




## 分类、规格与库存

管理台的“分类与规格”支持按商户管理商品分类、按商品管理规格及可售库存；商品编辑可填写所属分类编号。原商品价格继续对应编号最小的默认规格，默认规格不能单独删除。分类与商品须属于同一商户，有商品的分类不能删除。列表一次最多展示 100 个分类。

库存设置为可售数量的绝对值，预留数量不通过此接口修改；交易并发扣减等逻辑尚未实现。分类和规格写操作要求所属商户管理员权限；库存读取要求所属商户成员，库存写入要求商户管理员。当前仅供本地开发。现有数据库须已应用包含分类、SKU、库存表的迁移，迁移前请确认目标数据库及迁移内容。

## 管理员与商户成员权限

先注册并登录用户，通过 `GET /api/v1/users/me` 确认用户编号；核对 `NEXUSOPS_ENV` 和对应数据库后，在 `backend` 目录执行 `uv run python -m app.identity.bootstrap <用户编号>`。命令仅在不存在平台管理员时成功，不提供公开的初始化接口。MySQL 初始化使用数据库命名锁，SQLite 使用写锁。

平台管理员可创建商户（创建者同时成为该商户管理员）并管理商户成员。对于已有商户，平台管理员可通过成员接口为用户分配 `admin` 或 `staff`。商户管理员可管理本商户成员、商品、分类、规格和库存；员工可读取所属商户库存，但不能修改商品或管理成员。移除或降级最后一名商户管理员会被拒绝。平台管理员具有所有商户的管理权限，包括商户、商品、分类、规格、库存和成员管理。

`GET /api/v1/users/me/permissions` 返回当前用户的平台角色及有效商户成员关系；`GET/POST /api/v1/merchants/{merchant_id}/members` 和 `PATCH/DELETE /api/v1/merchants/{merchant_id}/members/{user_id}` 管理成员。需要登录的请求须携带 `Authorization: Bearer <access_token>`。公开查询仅显示启用的商户及其启用的商品、分类和规格；所属商户成员可以查看本商户停用数据，平台管理员可以查看全部数据。库存不是公开数据。

上述权限不等于生产就绪：操作审计、登录限流、令牌主动撤销和更细粒度的权限组仍待实现。

管理端“平台管理 → 用户管理”可查询用户、授予或撤销平台管理员，并按商户编号管理商户成员。对应的 `GET /api/v1/admin/users` 和 `PUT/DELETE /api/v1/admin/users/{user_id}/platform-admin` 仅平台管理员可调用；撤销时必须保留至少一名有效的平台管理员。商户管理员可以使用同一页面管理所属商户成员，但不能查询平台用户列表或调整平台角色。

平台管理员可在“用户管理”中创建普通用户，或调用 `POST /api/v1/admin/users`，提交 `username`、`mobile`、`password` 和可选的 `nickname`。账号密码按注册规则校验，创建时不自动授予角色，手机号标记为未验证；验证码登录成功后才记录验证时间。新增用户功能依赖迁移 `0003`，其他环境升级前请检查数据库目标及迁移内容。

首位平台管理员初始化时同时标记为超级管理员。超级管理员的平台管理员权限不能通过管理接口撤销；普通平台管理员仍可按现有规则授权或撤销。已初始化的旧环境需要单独确认并标记超级管理员，不能仅凭账号名自动推断。
